Differences:

- **Frequency selection and placement — standard `Model.forward` versus generated `FITS.forward`:** The standard retains bins `0:cut_freq`, including DC, and places projected bins starting at index zero. The generated version retains `1:cutoff+1` and places projected bins starting at index one. This changes both the input frequencies and their output interpretation. In particular, the generated model cannot learn an output DC correction through the projection.

- **Normalization — forward functions:** The standard uses `torch.var` with its default sample-variance correction; the generated model uses `unbiased=False`. This changes normalization scales and resulting predictions and gradients.
- **Parameter initialization — constructors:** The standard initializes a real `nn.Linear` and then casts it to complex, giving initially zero imaginary components. The generated code constructs a complex linear layer directly, using complex initialization. Identical seeds therefore do not imply identical initial parameters or training trajectories.
- **Inverse FFT length — forward functions:** The generated code explicitly supplies `n=lookback+horizon`; the standard omits `n`. They agree for even total lengths. For odd total lengths, the standard reconstructs one fewer time step, whereas the generated model reconstructs the requested length.
- **Training objective — standard `e.train(..., ft=True)` versus generated training loop:** The executed standard path minimizes MSE over the forecast horizon only. The generated code minimizes MSE against `torch.cat([x,y],1)` across reconstruction and forecasting. It therefore adds a backcast objective and weights the forecast contribution by its share of the total sequence length. This is a major experimental mismatch.
- **Validation arithmetic — standard `vali` versus generated `evaluate`:** Both mathematically compute equally weighted forecast MSE, but the standard computes float32 batch means before sample-weighted aggregation, while the generated code accumulates squared float64 errors. Small numerical differences could affect nearly tied validation selections.
